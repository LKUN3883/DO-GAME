# Boss 回归与输入驱动通关

基线：`d9f86d5b12e98a5237bcf1984bd55d67e94e89e4`。继续使用用户已确认的 Boss 镜头 Y 下限 -21。

## 修复与证据

新增4项 Boss Node 回归，在修改前全部失败，覆盖了以下确定问题：

1. 停顿结束进入霰弹段时，首发延后一 tick。现在进入段的同 tick 发出第一组，随后每0.9s一组，共4组、每组5颗。
2. 从 idleA 插入冲撞后总回步枪，跳过本应进入的霰弹段。现在记录打断停顿后对应的下一攻击段：idleA→霰弹，idleB→步枪。
3. 冲撞计算剩余步长却仍使用完整 `18*dt` 移动。现在用实际剩余位移，任何地形碰撞修正都结束冲撞并清零双轴速度。
4. Boss 死亡时在伤害阶段直接退出模式，并提前释放镜头。现在伤害末尾只标记 DEAD；清理阶段退出逻辑模式。死亡标记 tick 保持0.8s完整计时，从随后48个逻辑 tick计时；镜头、BossBar、DoorBoss在到时后解除，出口仍要求所有普通敌已死。

同时补上策划16.4规定的预警本体闪烁（实际 Canvas 像素检查有无变化），并修正 WIN 后移动鼠标仍改变 Aim 线：通关时保存瞄准方向，渲染沿用该值。

## 独立输入驱动通关

`scripts/input-playthrough.cjs` 从原关卡原始出生状态开始，只向游戏发送浏览器键鼠事件。测试服务器只附加只读状态快照函数；控制器从快照计算瞄准、移动、射击、近战、跳跃、钩爪输入。没有设置坐标、HP/ST/AMMO、无敌或敌人状态。

这是可读取全局敌人信息的**工具辅助测试**，不是人工试玩或盲玩。控制器的路线也不能代表所有打法。

本次记录（秒为控制器推进的游戏时间，另有开始前1秒落地等待）：
